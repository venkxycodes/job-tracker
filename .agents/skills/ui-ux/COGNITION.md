# Cognition

Use when design has many choices, dense information, complex workflows, weak prioritization, long forms, or users must remember state across steps.

## Core Principles

- Cognitive load: interface work consumes limited mental resources. Reduce irrelevant effort before adding instruction.
- Choice overload and Hick's Law: more options and more complex options slow decisions.
- Chunking and Miller's Law: group information into meaningful units instead of long unstructured lists.
- Working memory: keep needed state, choices, and constraints visible.
- Tesler's Law: some complexity is irreducible; decide whether user or system should carry it.
- Occam's Razor: among equally useful designs, prefer fewer concepts and assumptions.
- Pareto Principle: optimize common, high-impact tasks first.
- Parkinson's Law: tasks expand to available time; avoid ceremony that makes simple work feel large.
- Goal-gradient and Zeigarnik effects: visible progress and resumable unfinished work increase completion.

## Agent Checks

1. Identify primary task and remove controls/content that do not support it.
2. Replace raw option dumps with defaults, recommendations, categories, search, or progressive disclosure.
3. Split complex workflows into steps only when each step reduces decision load.
4. Keep required data visible near the action that uses it.
5. Prefer recognition over recall: examples, summaries, previews, inline constraints.
6. Move unavoidable complexity into validation, automation, sensible defaults, or guided setup.
7. Keep frequent paths short and rare paths available but not dominant.
8. Show progress, remaining steps, save/resume, and completion state.
9. Put key information or actions at the start/end of sequences, where recall is strongest.
10. Avoid multiple equally weighted primary actions in one region.

## Common Failure Modes

- Wizard with many steps but no progress or reason for each step.
- Advanced settings visible before user knows why they matter.
- Tables/lists with no grouping, filtering, sorting, or summary.
- Empty state that explains product philosophy instead of next action.
- Error messages that require users to remember prior screen state.
