# Navigation And Information Architecture

Use when reviewing page structure, menus, search, breadcrumbs, tabs, routes, labels, onboarding, or whether users can find what they need.

## Core Principles

- Self-evidence: interface should explain itself faster than users can ask for help.
- Scanning: users skim, choose first plausible path, and muddle through.
- Conventions: familiar labels, icons, links, buttons, and page patterns reduce effort.
- Wayfinding: users need to know where they are, what is available, and where to go next.
- Information architecture: group by user task and language, not system internals.
- Click clarity: fewer clicks are less important than obvious, confidence-building clicks.
- Search: offer fallback when content volume or category ambiguity makes navigation fragile.
- Serial position: users best remember first and last items in sequences.

## Agent Checks

1. Can user answer: where am I, what can I do here, where can I go next?
2. Do page title, route/link text, current nav state, breadcrumb, and heading agree?
3. Are navigation labels plain user terms, not clever names or internal nouns?
4. Is the current location visibly marked in nav, tabs, or breadcrumbs?
5. Are top-level categories mutually understandable and task-based?
6. Is search/filter available when browsing alone is likely to fail?
7. Are first and last nav items reserved for high-value destinations or actions?
8. Is content scannable through headings, short sections, lists, and visible hierarchy?
9. Does mobile navigation preserve orientation and primary task access?
10. Are instructions compensating for confusing IA that should be renamed or restructured?
11. Does every flow step have an obvious forward path, safe back path, and no dead end?
12. Are repeated navigation patterns consistent across screens?

## Common Failure Modes

- Route name, page heading, and sidebar item use three different terms.
- Key action hides inside overflow menu because layout copied desktop pattern to mobile.
- "Settings" becomes dumping ground for unrelated product concepts.
- Empty category pages offer no next path.
- Search returns raw technical results without user-readable titles or recovery.
