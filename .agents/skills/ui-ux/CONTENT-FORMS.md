# Content And Forms

Use when reviewing UX copy, headings, CTAs, onboarding, empty states, forms, validation, settings, labels, or beginner-friendly flows.

## Core Principles

- Good UX answers: what is this, why should I care, what do I do next?
- Copy should be direct, specific, user-language, and action-oriented.
- Visual hierarchy and content hierarchy work together; words are part of interface design.
- Forms should ask only what is needed now, in order users can answer.
- Defaults, examples, masks, and inline help reduce effort.
- Validation should prevent errors early and recover clearly.
- Progressive disclosure works when hidden information is secondary, not required for confidence.
- Beginner UX balances user goal and business goal; conflict should be explicit.

## Agent Checks

1. Does screen answer what, why, and next action within seconds?
2. Are headings concrete and task-specific?
3. Are CTAs written as user outcomes or verbs, not vague labels like "Submit" when specificity helps?
4. Are labels and options in user language?
5. Is helper text near the field/action it explains?
6. Are required fields minimized and grouped by user logic?
7. Does field order match how users gather information?
8. Are correct input controls used for data type and option count?
9. Are defaults safe and useful without hiding important consequences?
10. Does validation happen at the right time: inline for fixable errors, submit-level for cross-field rules?
11. Do error messages name issue, preserve input, and explain fix?
12. Are empty states, success states, and confirmations written with next action?

## Common Failure Modes

- CTA says "Continue" across several steps with different consequences.
- Placeholder text replaces persistent label.
- Form asks for optional data before user sees value.
- Error says "Invalid input" without allowed format or recovery.
- Empty state explains missing data but not how to create or import it.
